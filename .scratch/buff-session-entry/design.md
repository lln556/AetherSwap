# BUFF 登录检测与 Chrome 会话导入：首版设计

Status: ready-for-human
Created: 2026-10-30
Progress: implemented-and-verified

## 目标

用户无需等待交易报错或使用开发者控制台，即可检测 AetherSwap 保存的 BUFF 登录会话，并主动从本地 Chrome 导入可用会话。

## 已确认的使用流程

1. 首页 BUFF 卡片常驻“检测登录”“从浏览器导入”“手动填写”，显示最近检测时间。
2. 在线检测由用户主动触发；页面刷新只读取已有检测结果。已保存 Cookie 不等于验证有效。
3. 扩展首版以文件包和安装说明交付，用户手动安装；支持同一 Chrome 个人资料的普通窗口。
4. 用户在 BUFF 标签页完成登录后，从 AetherSwap 发起导入，并确认扩展显示的目标服务。
5. 扩展只访问用户授权的目标来源，授权精确到协议、主机、端口；新增来源重新授权。不后台读取上传 Cookie。
6. 服务器验证候选会话以及绑定 Steam 账号，与当前选中账号一致后才替换旧凭据；失败、无法核实或不匹配时保留原凭据，不自动切换账号。
7. 买入运行、待付款或有未核实订单时禁止替换；检测与交易启动分开。保存成功不自动启动买入，包括旧重登流程。
8. 需要安全验证时引导用户在本地 BUFF 完成验证，再主动导入。仅允许一次受控只读恢复检测；只有服务端验证通过才解除相关限制，限流冷却期间不重试。
9. 手动粘贴作为兜底入口，同样进行服务端验证并遵守替换保护。

## 状态语义

需要区分未配置、已配置但未检测、最近检测有效、登录失效、需要安全验证、请求冷却以及网络/服务异常。检测结果带时间，不将历史成功暗示为永久在线；新凭据不能沿用旧凭据的有效标记。网络错误不能直接标为登录失效。成功检测超过 30 分钟后转为需要重新检测，保留原检测时间，不自动请求 BUFF。

## 已确认的验收边界

- 公开 API：真实状态流转、只读验证、账号匹配、旧凭据保留、运行/待付款/未核实订单保护与保存后不自动启动。
- 恢复检测：风险限制与限流分别处理，重复点击不重复并发验证，验证期间不开放交易写入。
- Chrome 扩展：实际安装后的授权、目标来源匹配、用户主动导入、正常/未登录会话、未安装扩展提示及错误反馈；仅用测试会话，不导出用户真实 Cookie 作为测试材料。
- 桌面和手机页面：真实页面完成状态查看、检测、错误阅读、手动填写；扩展导入首版限定桌面 Chrome。
- 回归：已有 BUFF 登录、请求策略、支付保护、策略及交易流程测试。禁止测试真实下单或付款。

## 首版范围外

- Chrome 网上应用店发布、其他浏览器与无痕窗口。
- 后台持续同步 Cookie、跨 Chrome 个人资料读取。
- 自动切换账号、验证成功后自动启动买入。
- 绕过 BUFF 安全验证或限流。
- 此访谈不授权恢复最近买入的缺失订单；该问题需在登录恢复后另行核对。
