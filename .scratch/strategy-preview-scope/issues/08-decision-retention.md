# 08: 落实检查记录的保留、清理与不可用反馈

Status: ready-for-human
Progress: implemented-and-verified
Blocked by: 01
Spec: [策略预演与行情分析：第一版](../spec.md)
User stories: 34–40

**What to build:** 使用者能够在重启后查看近期检查记录；超过保留范围的数据自动清理，已清理或不支持的记录有明确提示，购买与成交历史不会受影响。

## Acceptance criteria

- [x] 保留最近 7 天、最多 10,000 条检查记录；任一限制达到时清理最旧记录，时间和数量口径在界面说明。
- [x] 清理同时处理关联预演数据，不形成无限增长的孤立版本；不得删除购买、成交、操作流水或正式策略。
- [x] 重启后有效期内记录仍可通过公开列表、详情和预演读取；覆盖 SQLite 与 PostgreSQL 支持的持久化行为。
- [x] 列表分页及详情正确反映清理结果；访问已过期或已清理记录时显示明确不可用反馈，不回退到示例结果。
- [x] 记录版本或输入无法支持预演时明确说明，不把不支持当作通过；已经保存的原始解释仍按记录展示。
- [x] 验证记录写入失败不改变正式规则判断，并在用户可见位置报告记录不可用；读取失败不伪装成正常空列表。
- [x] 检查记录和返回内容不泄露凭据、密钥、支付链接或无关完整配置，不因读取记录切换正式账户。
- [x] 通过公开接口和浏览器验证重启、7 天边界、10,000 条边界、关联清理、不可用反馈及业务历史保留，使用隔离数据库而非真实运行库。
