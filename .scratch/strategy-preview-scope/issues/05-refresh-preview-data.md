# 05: 主动获取完整行情并创建新的比较版本

Status: ready-for-human
Progress: implemented-and-verified
Blocked by: 02, 03
Spec: [策略预演与行情分析：第一版](../spec.md)
User stories: 12, 19, 23–27, 30, 39

**What to build:** 买入或普通上架的原记录缺少数据时，使用者可主动获取完整行情，查看进度，在新数据版本上同时比较原参数和临时参数，并继续查看原始检查。

## Acceptance criteria

- [x] 买入和普通上架详情提供主动刷新或获取完整行情操作，通过受现有鉴权保护的公开接口启动后台只读任务，并展示等待、运行、成功或失败结果。
- [x] 刷新数据覆盖当前比较所需且可获得的行情和业务上下文；仍不可获得的数据继续标为缺失，不伪造完整性。
- [x] 刷新创建关联原检查的新数据版本，保存新采集时间及来源，同时用该版本重新计算原参数与临时参数；不能混用旧基准和新参数结果。
- [x] 原检查记录、原始解释和此前数据版本保持不变，页面明确区分当时与新采集的判断；固定数据预演本身仍不联网。
- [x] 复用现有账号校验和限流；原账号不可用或会话已切换时不得静默使用其他账号。
- [x] 重复点击同一记录不启动并发刷新；任务失败、限流或进程中断时不宣称成功，保留原结果并反馈可理解的原因。
- [x] 刷新不修改正在启用的策略，不下单、付款、接受报价、撤单、上架、确认或创建调价任务；自动调价记录仍保持只读解释范围。
- [x] 通过后台任务、公开接口和浏览器验证缺数据后补取、同版本对照、旧记录保留、重复点击、账号变化、失败与限流。

## Implementation notes

依赖 02 和 03 是因为本票必须交付买入、普通上架两种完整数据获取和比较路径。关联版本沿用 01 的共用记录能力，清理规则由 08 管理。
