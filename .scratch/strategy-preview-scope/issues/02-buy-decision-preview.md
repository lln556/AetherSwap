# 02: 补齐完整买入规则的决策解释与预演

Status: ready-for-human
Progress: implemented-and-verified
Blocked by: 01
Spec: [策略预演与行情分析：第一版](../spec.md)
User stories: 8–11, 16, 18–22, 33

**What to build:** 使用者能够解释真实买入检查的通过、拒绝和数据失败，比较临时参数对价格、卖压、数量限制、历史稳定性和声明式模块判断的影响。

## Acceptance criteria

- [x] 在 01 的真实记录与界面路径上接入当前买入内置检查、数量及预算限制和安全声明式模块；正式流程和预演共用规则，不另写近似算法。
- [x] 对每个实际检查步骤显示实际值、有效参数和通俗原因，突出首个阻断步骤；未进入逐件检查的商品不虚构检查记录。
- [x] 保留正式流程的检查顺序、提前停止和请求行为；前置规则拒绝后不为预演额外请求后续行情。
- [x] 原检查在成本率阶段拒绝且没有历史行情时，放宽成本率后后续检查显示无法判断，不显示历史稳定性通过。主动补取由 05 提供。
- [x] 历史窗口和上下文依据记录中的评估时刻、有效配置、数据与币种计算，不使用当前时钟或当前行情替换旧依据；保留可供后续走势图展示的已有历史数据。
- [x] 声明式模块读取同一版本的业务上下文和前置输出；缺字段或不支持时明确报告，不以示例输出或默认通过掩盖缺失。
- [x] 数量、预算及其他启用限制在具备记录输入时参与比较；没有记录依据时明确列为缺项，不能根据现在的运行状态回填过去的判断。
- [x] 明确区分通过、拒绝、等待、数据不可用、不支持、未执行和未启用；单项通过不等于完整策略通过，更不等于已经下单。
- [x] 通过公开接口和实际买入检查路径验证规则一致性、原始记录不可变、缺数据场景及临时参数无副作用；浏览器可完成完整买入检查的阅读与比较。

## Implementation notes

本票交付完整买入规则的纵向路径；不依赖普通上架、主动刷新或图表完成。必要的规则提取在对应规则接入前完成，并保持正式行为不变。
