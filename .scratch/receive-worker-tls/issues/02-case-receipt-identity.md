# 裂空武器箱的已完成订单缺少可靠收货映射

Status: needs-info
Created: 2026-11-03

## 发现

10笔Fracture Case待收货订单在BUFF均为SUCCESS，价格、商品、买方Steam账号、付款时间等基础证据一致。Steam库存存在10个同名箱子，但这些物品没有磨损/模板信息，现有唯一指纹匹配不能使用。现场仅运行纯匹配计划得到0条可安全归属，未修改真实订单。

这与偶发TLS EOF是两个独立问题；网络恢复并不能让箱子自动匹配。

## 后续边界

研究订单/报价/Steam交易历史提供的可靠资产ID映射，再支持无磨损商品。不得凭名称与数量相同直接将个人库存认领为订单资产。当前修复只明确记录原因，保留待收货，不宣称该功能已支持。


## 实施方案（2026-11-03）

- 保留原有磨损/模板唯一指纹路径；无指纹商品改用 Steam 交易中的旧资产 ID → 新资产 ID 映射。
- 先用当前 Steam 登录会话读取交易历史并校验账户。已结算交易通过账户已有的 Web API key 只读查询 GetTradeStatus；不自动创建 key。
- BUFF 原资产 ID、Steam 入库方向、完成状态、数量、classid、付款时间以及当前库存的新资产 ID / context / 名称均须一致，重复映射全部拒绝。
- 补记和无敏感信息的交易映射审计在同一数据库事务内提交；账户切换、证据缺失、网络失败均保留待收货。
- 相同会话与目标资产的查询缓存 5 分钟，避免后台轮询反复访问 Steam。

## 现场限制

2026-11-03 现场只读证据：10 笔 BUFF SUCCESS 订单的旧资产 ID 全部位于同一笔 Steam 入库交易。该交易北京时间 2026-11-03 08:54:28 发起，Steam 返回 time_settlement 对应 2026-11-10 09:00。网页 token 接口返回旧资产 ID 和结算时间，但无 new_assetid；已有 key 的 GetTradeStatus 对该交易返回空响应。传统接口对已结算的旧交易返回新资产 ID。

因此当前 10 笔必须等待保护期结束后再次核实；不能把“程序支持了映射”描述为“当前 10 笔已经完成归属”。若届时仍无映射，继续保留待收货并提示原因。未根据同名数量、库存历史相邻行或物品顺序强行认领。


## 追加核实

一笔 2026-10-26 的历史交易已过 Steam 返回的结算时间，但 legacy GetTradeHistory 仍只返回交易头（无资产数组），GetTradeStatus 仍返回空响应。因此不能保证 11 月 10 日到点即可自动归属；目前未找到公开可靠接口提供这类交易的资产映射。代码按实际可用证据执行，空响应作为“尚无资产映射”，不伪装成请求错误。当前十笔的自动补记仍受上游数据缺失限制。

实现验证：完整隔离回归 1279 passed；之后为真实出现的 legacy 空响应补充独立回归，并重新执行相关测试。现场只读验证准确返回 10 笔保护期记录、0 笔可归属、无请求错误；未写入这十笔资产归属。
